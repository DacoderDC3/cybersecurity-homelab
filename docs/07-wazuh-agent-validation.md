Wazuh SSH Detection Validation

Objective

Validate that Wazuh can detect and correlate SSH authentication failure activity from monitored Linux systems using a controlled lab scenario.

This lab tested whether failed SSH login attempts were recorded in Linux authentication logs, processed by Fail2ban, collected by the Wazuh agent, and visible in the Wazuh dashboard as security-relevant events.

Scenario Summary

A controlled SSH login failure scenario was performed against a monitored Linux VM in the homelab.

The goal was to generate safe authentication failure events and confirm that the activity appeared across multiple evidence sources:

* /var/log/auth.log
* /var/log/fail2ban.log
* Wazuh dashboard alerts
* Wazuh agent telemetry

This confirmed that Wazuh was receiving and interpreting endpoint log data correctly.

Test Method

A controlled SSH login failure was generated by attempting to authenticate to a monitored Linux VM with incorrect credentials.

This created authentication failure events in the Linux authentication log. Fail2ban also recorded related activity, and Wazuh collected the logs through the installed agent.

The test was performed only inside the lab environment.

Evidence Sources

Linux Authentication Log

The Linux authentication log was reviewed to confirm that the failed SSH login activity was recorded locally.

Log source:

/var/log/auth.log

Fail2ban Log

The Fail2ban log was reviewed to confirm that the failed authentication activity was also visible to the host-based protection layer.

Log source:

/var/log/fail2ban.log

Wazuh Dashboard

The Wazuh dashboard was reviewed to confirm that the event was collected and surfaced centrally.

This validated that the Wazuh agent was correctly forwarding relevant security telemetry to the Wazuh Manager.

Validation Results

The test successfully confirmed that:

* Failed SSH login activity was written to /var/log/auth.log.
* Related activity was visible in /var/log/fail2ban.log.
* Wazuh collected the relevant log activity from the monitored endpoint.
* Wazuh displayed security events related to the controlled SSH failure scenario.
* The Wazuh agent and manager were functioning as expected for this detection use case.

Detection and Correlation Notes

This lab demonstrated basic detection correlation by comparing local endpoint logs with centralized Wazuh alerts.

The same activity was visible from multiple perspectives:

Source	Purpose
auth.log	Confirms the Linux system recorded the SSH authentication failure
fail2ban.log	Confirms Fail2ban observed the suspicious authentication pattern
Wazuh Dashboard	Confirms the SIEM centrally collected and displayed the event

This is important because a security analyst should not rely on only one source of evidence. Correlating local logs with central SIEM alerts improves confidence during investigation.
